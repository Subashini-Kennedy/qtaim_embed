1. Added val_dataset_loc — this is the most important fix. Without it, the data module ignores your val_43k.pkl entirely and randomly carves a validation set out of the training data based on val_prop. You'd be training on fewer samples than you think and validating on a random cut.
2. Removed homo/lumo/gap from extra_keys["global"] — extra_keys is for input features, not prediction targets. Those three values are already declared as targets via target_list. Putting them in extra_keys would feed them as input features to the model (leaking the labels!) and inflate global_feature_size incorrectly.
3. Set atom_feature_size, bond_feature_size, global_feature_size to 0 — the training script calls dm.prepare_data() first and then overwrites these three fields with the real values (lines config["model"]["atom_feature_size"] = feature_size["atom"] etc.). Hardcoding them to wrong values risks a silent mismatch if the pipeline doesn't overwrite them. Setting them to 0 makes any failure loud and obvious.
4. Set val_prop and test_prop both to 0.0 — since you're providing all three splits as separate files, random splitting should be fully disabled.
